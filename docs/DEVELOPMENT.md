# 开发、测试与环境

本页描述待建立的工程规范。当前没有 package.json、应用和部署环境，下列命令是目标命令，尚不可运行。

## 开发节奏

1. 从 ROADMAP 选择当前清单项，读取相关契约，先解决会影响该实现的待决问题。
2. 对业务规则和安全边界先写能表达预期行为的失败测试，再实现、重构并复跑；不以安装失败代替行为失败。
3. 使用真实独立 MongoDB 做持久化和索引集成验证；外部 OAuth 可以做边界模拟，但真实登录另记结果。
4. 跑与改动有关的检查，里程碑验收补完整核心流程及独立只读审查；发现阻塞则修复复核。
5. 在 ROADMAP 简记真实证据。提交与推送按当前用户授权和工作流执行。

测试断言消费者可观察行为、边界和安全，不把源码存在、mock 回声或单纯“不抛异常”当成功。保留数据校验、越权、脱敏、会话撤销、并发唯一性与限流检查，不要求每处措辞调整都套完整 TDD 流程。

## 环境划分

| 环境 | 用途 | 隔离要求 |
|---|---|---|
| local development | 本地调试与演示 | 开发库及演示数据，可重建 |
| local test / CI | 自动化验证 | 独立库、独立凭据；清理命令只能命中本任务测试资源 |
| staging | 线上部署验证与流程回归 | 独立域名/访问地址、数据库、密钥和 OAuth 回调；不接触生产数据 |
| production | 对外提供服务 | 生产凭据、受控发布、备份、监控与回滚 |

先建立本地开发/测试隔离，在首轮部署时建立 staging，在正式开放前完成 production。尽量使用同一源码与构建产物，以环境配置区分部署。具体供应商、域名和资源预算尚待选择。

配置提供无密钥的 .env.example；真实数据库 URI、OAuth secret、Cookie secret 等不入库、不进日志或验收附件。启动时校验必要配置；不允许测试静默回退到开发库或生产库。

## 待建立的命令

| 命令 | 预期职责 |
|---|---|
| pnpm dev | 手动启动本地开发服务 |
| pnpm typecheck / pnpm lint | 类型与静态检查 |
| pnpm test | 离线测试，一次运行后退出 |
| pnpm test:integration | 使用独立真实测试库，依赖不可用时失败 |
| pnpm build | 构建 web/API/shared contracts |
| pnpm smoke | 核心流程验证，清理自己启动的进程 |
| pnpm db:dev:up / pnpm db:dev:down | 开发数据库生命周期 |
| pnpm db:test:up / pnpm db:test:reset / pnpm db:test:down | 测试数据库生命周期；reset 验证隔离与可重复性 |

M1 首次生成并提交 lockfile 后，干净 checkout 使用 pnpm install --frozen-lockfile 验证。工具与数据库版本在实现时验证后固定，不能将未验证的版本号写为已通过。

## 发布与技术实验

CI 至少覆盖类型、lint、行为测试、构建和数据库集成；浏览器核心流程在里程碑和发布前执行。接口方法、路径、状态码及 DTO 应联合验证，防止契约漂移。

发布前验证 Cookie、CORS/CSP、限流、日志、索引、健康检查；备份需做恢复演练，回滚需区分应用版本与数据库变化。生产部署目标、凭据和操作授权未明确前，只做本地或已授权环境准备。

缓存、队列等学习实验放在对应功能之后，记录目的、方案、可复现验证和结果，必要时新增一份 ADR；没有采纳的实验不进入生产主流程。不预建微服务、消息队列或缓存空壳。

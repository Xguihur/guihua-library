## 3. M2a：账号、密码与会话

### 3.1 输入与身份规则

以下为本阶段采用的设计决定；批次 A 已同步 HTTP/错误契约与 DECISIONS，并建立 `docs/adr/0002-account-and-session.md` 冻结身份与安全取舍，再进入实现。如存在现有约束冲突，先记录并解决，不静默另选规则。

- 注册严格接受 `{email, username, password}`；登录严格接受 `{identifier, password}`。拒绝未知字段，尤其 roles、role、权限、userId、passwordHash。密码不 trim、不截断、不进行 Unicode 归一化。
- 用户名：去除首尾空格后，匹配 `^[A-Za-z][A-Za-z0-9_]{2,31}$`；展示保留大小写，唯一键 `usernameNormalized` 为 ASCII 小写；用户名登录大小写不敏感。非法用户名固定 `400 INVALID_USERNAME`；其余输入格式错误 `400 VALIDATION_ERROR`。
- 邮箱：trim 后整体小写，合法邮箱格式且最长 254 字符；不执行供应商特有的去点或去加号处理。邮箱登录同样归一化。密码长度 12–128 个 Unicode 码点，另设 UTF-8 最大 512 字节，不强制字符种类。
- 重复归一化用户名/邮箱固定 `409 IDENTITY_CONFLICT`，以数据库唯一索引及重复键映射为最终保证；并发注册仅一个成功，不能只靠先查后写。登录失败统一 `401 INVALID_CREDENTIALS`，不区分不存在、密码错误、禁用或无本地密码；不存在账号也执行等价密码校验工作，避免明显时序分支。
- 不接受客户端角色。新用户固定普通 user；会话响应角色来自服务端。M2 有效业务权限为 `[]`，M3/M4 再按实际交付能力扩展。

### 3.2 密码与数据模型

- 优先 Node 原生异步 `crypto.scrypt`，每个密码使用独立随机 salt；哈希编码包含算法、参数、salt 和结果，比较采用恒时比较。实施前依据官方资料确定参数与 maxmem，记录安全依据及本机校验耗时；不自创密码算法，不使用同步 KDF 阻塞请求。
- 扩展现有 users：用户名归一化键、可空邮箱/密码哈希（支持 OAuth-only）、emailVerifiedAt（默认 null）、gender、signature、enabled 和时间字段。gender 为 `unspecified|male|female|other`，默认 unspecified；signature 默认空串，avatarUrl 默认 null，enabled 默认 true。
- 归一化用户名唯一；可空邮箱使用仅匹配字符串的 partial unique index，不能让多个 OAuth-only 用户因 null 邮箱冲突。身份使用独立集合，`{provider, subject}` 复合唯一并关联不可变 userId，另设 `{userId, provider}` 唯一索引，每个账号最多绑定一个 GitHub 身份。邮箱密码是同一用户的可选登录方式，不新建另一个用户。GitHub 身份删除后不保留可继续登录的映射。
- 提供可重复执行、仅作用于本地开发库的 M1 数据迁移/回填方案：先检查大小写归一化冲突，发现冲突停止并报告脱敏摘要，不自动改用户名或合并账号。旧索引替换顺序和回滚限制写入 ADR；不能对未知数据执行自动 syncIndexes/dropDatabase。
- M1 seed 不是可登录账号凭据来源；不猜测/复用示例 passwordHash。需要登录夹具时仅在测试库生成真实哈希；本地演示账号需显式配置，不提交明文固定密码。

### 3.3 会话、Cookie 与请求防护

- MongoDB 保存服务端会话，浏览器只持有至少 32 字节随机不透明 token；数据库只存 token 的 SHA-256 摘要、userId、createdAt、expiresAt。固定 7 天有效期，不做滑动续期；TTL 索引用于清理，查询必须显式检查到期，不能依赖 TTL 删除及时性。
- 注册成功自动创建会话；登录/注册成功总是新建 token，替换当前浏览器旧会话并撤销旧 token，防止会话固定。退出撤销当前会话并清 Cookie；无效、缺失、过期 Cookie 退出仍 204。数据库异常不能假称退出撤销成功，应返回脱敏 503。
- 每次受保护请求从数据库检查会话及用户 enabled，不缓存可继续放行的旧状态；禁用或删除用户后旧会话立即 401。M2 无管理禁用接口，通过测试夹具验证该规则。
- Cookie：`guihua_session`，HttpOnly、SameSite=Lax、Path=/、无 Domain，Max-Age 与服务端期限一致；生产强制 Secure，本地 HTTP 明确允许非 Secure；清除时属性匹配。不使用 localStorage 保存认证凭证，不在 URL 或响应 DTO 返回 token。
- 浏览器走同源 `/api`（开发 Vite proxy），默认不开放跨源凭据 CORS。所有浏览器 JSON 写请求（含注册、登录、退出）要求配置的精确 Origin 白名单及 `application/json`，恶意/缺失/null Origin 拒绝 403，错误 Content-Type 返回 400；真实 HTTP 测试显式携带 Origin。PATCH 的未知字段严格拒绝，禁止通过表单绕过防护。OAuth GET 回调按 state/PKCE 单独保护。
- 注册：每 IP 15 分钟最多 5 次；登录：每 IP 15 分钟 30 次、每归一化 identifier 15 分钟 10 次；OAuth 入口每 IP 15 分钟 20 次，计数覆盖成功/失败尝试；超限 429 RATE_LIMITED 并带 Retry-After。单实例本地先使用有界且自动淘汰的内存存储，明确重启重置、多实例无共享限制；多实例上线前改共享存储。仅信任显式配置的代理，不能直接信任任意 X-Forwarded-For；测试使用可控时钟，不实际等待窗口。

## 4. HTTP 与 DTO 细化

沿用现有资源路径，批次 A 将以下精确形状写回 contracts，运行时 schema、共享类型及 HTTP 断言保持一致。

| 方法与路径 | 输入 | 成功 |
|---|---|---|
| POST /api/users | email、username、password | 201 UserPublic，设置会话 Cookie |
| POST /api/sessions | identifier、password | 201 SessionCurrent，设置会话 Cookie |
| GET /api/sessions/current | 无 | 200 SessionCurrent；失效 401 |
| DELETE /api/sessions/current | 无业务字段 | 204，无响应体 |
| GET /api/me | 无 | 200 UserPublic；失效 401 |
| PATCH /api/me | username/gender/avatarUrl/signature 的非空子集 | 200 更新后的 UserPublic |

- UserPublic：`{id, username, gender, avatarUrl, signature, createdAt}`；id 字符串，createdAt ISO 时间。公共作者投影保持 M1 的 `{id, username, avatarUrl}`，不自动扩大。
- SessionCurrent：`{user: UserPublic, roles: string[], permissions: string[], expiresAt: string}`；角色/权限只在认证响应出现。不得包含 session token/摘要、邮箱、密码哈希、OAuth subject/token 或内部字段。
- 会话错误沿用 `401 UNAUTHORIZED`；非法 Origin 为 `403 FORBIDDEN`；依赖失败为脱敏 503。数据库写入/会话创建中途失败不得留下可用孤儿身份或无法恢复的注册状态；本阶段选用 MongoDB 事务保证用户、身份、挑战消费和凭据变更的一致性；由实施会话将 dev/test 双库分别配置为独立单节点 replica set（批次 A/B 已完成，见 §9），更新 URI、启动等待、CI 模板、smoke 和隔离验证，不能让两个环境共用副本集或假设 standalone 支持事务。外部换 token/发邮件不放入长事务；先完成外部调用，再用事务校验状态并落库。
- 替换 M1 固定拒绝的 AuthenticatedGuard，但 M2 不开放写书或写评论：匿名 POST 保持 401，有效会话 POST 返回 `403 FORBIDDEN`（能力未开放），且数据不变；同步占位 controller 和测试，不让有效会话继续得到误导的 401，也不提前实现 M3。

## 5. M2b：个人资料与界面

- PATCH 只允许四个可编辑字段，空对象/未知字段拒绝；不允许 email、roles、enabled、id 或 ownerId。username 与注册同规则；大小写仅展示变化可成功，与其他用户归一化冲突返回 409。
- signature 最长 200 Unicode 码点，作为纯文本；拒绝 C0 控制字符（允许换行及制表符），不使用 v-html。gender 只接受上述枚举。
- avatarUrl 仅 null 或最长 2048 字符的 HTTPS 绝对 URL，禁止 userinfo、控制字符及非 HTTPS 协议；不代理抓取、不上传。外链图片使用 no-referrer，失败显示占位；现有 M1 头像如不符合新写入规则，可继续只读显示，不擅自重写数据。
- 前端提供注册、登录、资料页面与导航登录态、退出入口；密码字段正确 autocomplete、label、键盘焦点、提交中禁重复点击、明确错误与重试。登录后只允许回到同源站内安全路径，拒绝外站和 `//` 重定向。
- 刷新时通过 current 恢复身份；401 清空本地登录态，网络/503 显示重试，不能当作明确退出。退出成功后清理资料缓存，资料响应不能在退出后被慢请求回写；登录成功密码不持久化。用户名更新应在重新读取书籍/评论时展示最新公开作者资料，不改资源归属。

## 6. M2c：GitHub 与统一登录方式

> 批次 E 已完成本地实现与验证（见 §9）：`GET /api/oauth/github/authorization`、`GET /api/oauth/github/callback`、`GET /api/me/login-methods`、`POST /api/me/identities/github/authorizations`、`DELETE /api/me/identities/github`、`POST /api/sessions/current/reauthentications`、`POST /api/sessions/current/github/authorizations`、`POST /api/me/password-credentials/verifications`、`POST /api/me/password-credentials` 均按下列规则实现。浏览器回调默认 302 固定结果页；带 `Accept: application/json` 时返回契约错误状态（如绑定冲突 409）。真实 GitHub 外部流程因缺少凭据未验证，仅用明确标注的模拟替身覆盖协议与数据库行为。

### 6.1 账号语义与直接登录

- 所有资料、书籍、评论只归属不可变站内 userId。邮箱密码与 GitHub subject 都指向该用户；GitHub 改名/换头像不创建新账号，不自动覆盖站内资料。
- 未登录点击 GitHub：已有 subject 直接登录原账号；新 subject 在事务中创建普通站内用户及身份，立即建立普通会话。用户名自动生成为 `gh_` 加安全随机 ASCII 后缀，满足长度/字符规则，碰撞有界重试；之后可在资料页修改。不再设置首次用户名必填页或 `/oauth/github/registrations` 端点，不以未填资料限制已创建用户。
- OAuth-only 用户初始 email/passwordHash 均为 null。不以 GitHub 邮箱查找、合并或占用已有邮箱账号；头像可按本站 HTTPS 规则初次导入，失败采用 null，不影响注册。
- 登录页说明“已有账号请先登录，再在账号设置绑定 GitHub”。未登录直接授权无法识别用户的已有邮箱账号，因此可能创建第二个账号；不猜测、不自动迁移两者内容。GitHub 已被其他账号绑定时仅报告冲突，合并已有账号不在 M2 范围。
- 已登录时普通 GitHub 登录入口不得隐式切换用户或绑定；返回明确引导，在账号设置使用独立绑定入口。

### 6.2 OAuth 协议及绑定

- 登录入口 `GET /api/oauth/github/authorization`；绑定入口为受保护的 `POST /api/me/identities/github/authorizations`（JSON 空对象，201 `{authorizationUrl}`）；统一回调 `GET /api/oauth/github/callback`。绑定入口要求有效会话、Origin 校验和近期身份复核。
- 使用服务端授权码流程、随机 state、PKCE S256、短期 HttpOnly 浏览器绑定 Cookie。服务端过渡记录保存 state 摘要、verifier、purpose（login/link/reauth）、目标 userId（如有）、原会话标识、固定返回位置和 expiresAt（10 分钟）。purpose/userId 只能由服务端生成，不能由回调参数覆盖。
- 按 GitHub [官方 Authorizing OAuth Apps 文档](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps)确认授权码流程、PKCE S256 与回调配置；严格校验 state、浏览器绑定、有效期、一次性消费和同一发起会话。本地证据仅覆盖协议与数据库行为，不等于对 github.com 的真实授权验证。绑定期间退出/切换账号/禁用/会话失效，必须拒绝回调；防止把攻击者的 GitHub 绑定到受害者账号。
- 后端换 token 并查询稳定 GitHub user id 作为 subject；不信任浏览器提交的 subject，不使用可变 login/邮箱作主键。token 仅用于本次查询，不持久化、不回传、不落日志，默认不申请邮箱范围。
- 绑定同一账号已绑定的同一 subject 可幂等成功；subject 已属于其他账号、当前账号已绑定其他 GitHub 时返回 `409 IDENTITY_CONFLICT`，不覆盖、不转移、不创建新用户。浏览器回调重放仍拒绝，不因业务幂等而放松协议校验。
- 并发首次登录、绑定/解绑、添加密码方式均需事务及唯一索引保证；凭据变更在 user 上使用同一版本更新串行化并发判断，不能出现零登录方式、双重归属或孤儿用户。事务冲突有界重试，失败返回稳定错误。
- 成功后回站内固定页面，回调立即跳转移除 code/state 查询串，不渲染加载第三方资源的中间页面；日志屏蔽 OAuth 查询串。取消授权、过期、重放、上游超时等显示稳定错误，不接受任意 returnTo。

### 6.3 登录方式管理与近期身份复核

- 账号设置明确显示 GitHub 是否绑定、邮箱密码是否可用、可操作入口；`GET /api/me/login-methods` 返回 `{github: {linked: boolean}, password: {enabled: boolean, email: string|null}}`，仅本人可读，邮箱不得流入公共 DTO。每个账号必须至少保留一种可用方式。
- 敏感操作要求最近 5 分钟的显式身份复核，证据绑定当前 session/user/purpose，服务端保存、过期检查；旧会话本身不等于复核。密码用户通过 `POST /api/sessions/current/reauthentications` 提交 `{password}`，成功 204；GitHub 用户通过 `POST /api/sessions/current/github/authorizations`（201 `{authorizationUrl}`）重新 OAuth，并确认 subject 属于当前用户，不能用另一个 GitHub 的授权通过复核。
- GitHub 复核需站内明确点击发起、新的 state/PKCE 流程和同 subject 校验；回调返回设置页要求再次明确确认操作。不能宣称 GitHub 必然重新询问密码：上游可能已有登录会话。该限制写入 ADR；解绑另需已验证邮箱和密码作为保底，添加密码还需邮箱一次性验证，不能单凭旧本站 Cookie 完成。
- `DELETE /api/me/identities/github`：需要近期复核，且存在已验证邮箱和有效密码哈希，成功 204；未绑定且已有其他方式时幂等 204；删除最后登录方式返回 `409 LAST_LOGIN_METHOD`。M2 不提供删除密码登录方式、直接更换 GitHub 或账号合并。
- 绑定、添加密码或解绑成功后撤销其他会话，轮换当前 session token 并清除复核证据；当前用户保持登录，旧 token 不再可用。用户 enabled 与账户版本在事务内重新检查，不能凭过时状态变更凭据。

### 6.4 GitHub 用户添加邮箱密码登录

- 添加密码仅允许当前无密码方式的已登录用户；已有密码方式仅允许验证其原邮箱（完成时不接收 password），不能覆盖凭据。先近期身份复核，再 `POST /api/me/password-credentials/verifications`，body `{email}`，202 固定确认消息；不在此步接收或存储新密码，不透露邮箱是否被占用。
- 使用 SMTP 发送验证链接；开发/测试采用仅本地绑定、明确隔离的邮件捕获服务，生产 SMTP 尚未配置时该功能返回脱敏 503，不能伪称邮件已发送。由实施会话选择成熟 SMTP 库并补环境变量示例及启动说明，不自己实现 SMTP（批次 E 未实施）。
- 验证 token 至少 32 字节随机，数据库仅存摘要，10 分钟有效，绑定 userId、归一化 email、当前 session 和用途；新请求使旧挑战失效。发送失败不能保留可用挑战，不能把 token 返回 API 或写日志；投递过程有界超时。
- 邮件链接进入本站固定页面，token 放 URL fragment，页面读取后立即移除 fragment，不加载第三方资源、不保存到持久化存储。GET 打开链接不直接修改凭据；用户输入新密码，前端经同源 JSON `POST /api/me/password-credentials` 提交 `{token,password}`。
- 完成必须是发起挑战的同一有效会话，并再次满足近期身份复核；跨浏览器打开时提示返回原浏览器操作，不能自动转移会话。过期复核可重新执行，不能跳过。
- 在事务内一次性消费挑战、重新检查用户仍无密码方式、验证邮箱唯一、设置 verified 邮箱和安全密码哈希；已占用邮箱返回 409 IDENTITY_CONFLICT，绝不绑定已有账号或覆盖旧密码。无效/过期/重放 token 返回 `400 VALIDATION_ERROR`，已有密码方式返回 409 IDENTITY_CONFLICT。竞态失败不允许覆盖获胜请求。
- 完成后可用该邮箱或站内用户名加密码登录同一个 userId，历史资料、书籍与评论归属完全一致。此功能不是密码重置；普通邮箱注册仍不强制验证，但该邮箱未验证时不能作为解绑 GitHub 的保底登录方式。账号同时有未验证本地邮箱和 GitHub 时，可通过同一验证挑战确认原邮箱（不得更换），完成仅设置 verified 标记、不覆盖原密码；完成端点此分支仅接受 `{token}`。普通邮箱用户完成验证并复核后也可安全解绑 GitHub。
- 发送验证邮件按 IP 每小时 10 次、用户每小时 5 次、归一化目标邮箱每小时 5 次；提交/身份复核按会话每 15 分钟 10 次（密码复核另受登录限流）；429 带 Retry-After。输入严格白名单，不把服务端字段传给客户端控制。

### 6.5 外部依赖与完成门槛

- 缺 GitHub client id/secret 时其他功能仍能启动，相关入口明确不可用并返回脱敏 503；缺 SMTP 时邮件相关功能同理。只记录配置名、占位与固定回调，不提交真实凭据。
- 提供 GitHub OAuth App 创建步骤、Client ID/Secret 配置、开发与线上分离的回调说明（参数与 PKCE 以[官方文档](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps)为准）；真实外部授权由用户完成，不能索要 GitHub 密码/PAT 冒充 OAuth 凭据。所有浏览器跳转只使用经严格校验的 `WEB_BASE_URL` 与服务端固定路径，不接受请求的 `returnTo`。
- 生产 SMTP 必须显式启用 TLS：`SMTP_SECURE=true` + 端口 465（隐式 TLS）或 `SMTP_SECURE=false` + `SMTP_REQUIRE_TLS=true` + 端口 587（强制 STARTTLS）；本地 Mailpit 保持两个开关为 `false`。说明见 [DEVELOPMENT](../DEVELOPMENT.md) 与 `.env.example`。生产投递仍未验证，不得写成已完成。
- 验收必须覆盖真实 GitHub 登录、绑定及后续重新登录，以及本地捕获邮件取链接完成验证（非仅 mock 发信）。部署前另验真实 SMTP 投递；当前无部署环境应明确该项未验证。缺 GitHub 授权条件时可继续其他批次，但整个 M2 标记外部验证阻塞，不能删功能或宣称完成。

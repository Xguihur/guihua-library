## 1. 目标、范围与交付顺序

形成“访客浏览 → 邮箱注册/登录 → 刷新保持会话 → 查看和修改资料 → 退出撤销”的完整流程，再接入 GitHub 登录。按 M2a、M2b、M2c 顺序实施，每批可单独验收；M2a 通过不代表整个 M2 完成。

- M2a：邮箱注册、邮箱/用户名密码登录、当前会话、退出、真实会话守卫、密码哈希、限流、Cookie 与 CSRF 防护及前端流程。
- M2b：个人资料读取和修改、用户名唯一性、头像来源及输入安全。
- M2c：GitHub OAuth、首次用户名设置、身份并发唯一性与真实登录验证。
- 不包含书籍/评论写入、个人书籍列表 `/api/me/books`（随 M3）、管理员界面、角色编辑、上传、邮箱变更、密码修改/找回、验证码、强制邮箱验证及生产部署。首版不实现账号关联界面/端点；不能静默合并身份。
- 保留 M1 公开书库、分页、隐藏资源隔离、错误结构与数据库安全约束。用户学习注释原样保留，不删减、不改写，不以整理代码为由移除。

## 3. M2a：账号、密码与会话

### 3.1 输入与身份规则

以下为本阶段采用的设计决定；实施批次 A 先同步 HTTP/错误契约、DECISIONS，并建立 `docs/adr/0002-account-and-session.md` 冻结身份与安全取舍，再写实现。如存在现有约束冲突，先记录并解决，不静默另选规则。

- 注册严格接受 `{email, username, password}`；登录严格接受 `{identifier, password}`。拒绝未知字段，尤其 roles、role、权限、userId、passwordHash。密码不 trim、不截断、不进行 Unicode 归一化。
- 用户名：去除首尾空格后，匹配 `^[A-Za-z][A-Za-z0-9_]{2,31}$`；展示保留大小写，唯一键 `usernameNormalized` 为 ASCII 小写；用户名登录大小写不敏感。非法用户名固定 `400 INVALID_USERNAME`；其余输入格式错误 `400 VALIDATION_ERROR`。
- 邮箱：trim 后整体小写，合法邮箱格式且最长 254 字符；不执行供应商特有的去点或去加号处理。邮箱登录同样归一化。密码长度 12–128 个 Unicode 码点，另设 UTF-8 最大 512 字节，不强制字符种类。
- 重复归一化用户名/邮箱固定 `409 IDENTITY_CONFLICT`，以数据库唯一索引及重复键映射为最终保证；并发注册仅一个成功，不能只靠先查后写。登录失败统一 `401 INVALID_CREDENTIALS`，不区分不存在、密码错误、禁用或无本地密码；不存在账号也执行等价密码校验工作，避免明显时序分支。
- 不接受客户端角色。新用户固定普通 user；会话响应角色来自服务端。M2 有效业务权限为 `[]`，M3/M4 再按实际交付能力扩展。

### 3.2 密码与数据模型

- 优先 Node 原生异步 `crypto.scrypt`，每个密码使用独立随机 salt；哈希编码包含算法、参数、salt 和结果，比较采用恒时比较。实施前依据官方资料确定参数与 maxmem，记录安全依据及本机校验耗时；不自创密码算法，不使用同步 KDF 阻塞请求。
- 扩展现有 users：用户名归一化键、可空邮箱/密码哈希（支持 OAuth-only）、gender、signature、enabled 和时间字段。gender 为 `unspecified|male|female|other`，默认 unspecified；signature 默认空串，avatarUrl 默认 null，enabled 默认 true。
- 归一化用户名唯一；可空邮箱使用仅匹配字符串的 partial unique index，不能让多个 OAuth-only 用户因 null 邮箱冲突。身份使用独立集合，`{provider, subject}` 复合唯一并关联不可变 userId。
- 提供可重复执行、仅作用于本地开发库的 M1 数据迁移/回填方案：先检查大小写归一化冲突，发现冲突停止并报告脱敏摘要，不自动改用户名或合并账号。旧索引替换顺序和回滚限制写入 ADR；不能对未知数据执行自动 syncIndexes/dropDatabase。
- M1 seed 不是可登录账号凭据来源；不猜测/复用示例 passwordHash。需要登录夹具时仅在测试库生成真实哈希；本地演示账号需显式配置，不提交明文固定密码。

### 3.3 会话、Cookie 与请求防护

- MongoDB 保存服务端会话，浏览器只持有至少 32 字节随机不透明 token；数据库只存 token 的 SHA-256 摘要、userId、createdAt、expiresAt。固定 7 天有效期，不做滑动续期；TTL 索引用于清理，查询必须显式检查到期，不能依赖 TTL 删除及时性。
- 注册成功自动创建会话；登录/注册成功总是新建 token，替换当前浏览器旧会话并撤销旧 token，防止会话固定。退出撤销当前会话并清 Cookie；无效、缺失、过期 Cookie 退出仍 204。数据库异常不能假称退出撤销成功，应返回脱敏 503。
- 每次受保护请求从数据库检查会话及用户 enabled，不缓存可继续放行的旧状态；禁用或删除用户后旧会话立即 401。M2 无管理禁用接口，通过测试夹具验证该规则。
- Cookie：`guihua_session`，HttpOnly、SameSite=Lax、Path=/、无 Domain，Max-Age 与服务端期限一致；生产强制 Secure，本地 HTTP 明确允许非 Secure；清除时属性匹配。不使用 localStorage 保存认证凭证，不在 URL 或响应 DTO 返回 token。
- 浏览器走同源 `/api`（开发 Vite proxy），默认不开放跨源凭据 CORS。所有浏览器 JSON 写请求（含注册、登录、退出）要求配置的精确 Origin 白名单及 `application/json`，恶意/缺失/null Origin 拒绝 403，错误 Content-Type 返回 400；真实 HTTP 测试显式携带 Origin。PATCH 的未知字段严格拒绝，禁止通过表单绕过防护。OAuth GET 回调按 state/PKCE 单独保护。
- 注册：每 IP 15 分钟最多 5 次；登录：每 IP 15 分钟 30 次、每归一化 identifier 15 分钟 10 次；OAuth 入口每 IP 15 分钟 20 次，计数覆盖成功/失败尝试；超限 429 RATE_LIMITED 并带 Retry-After。单实例本地先使用有界且自动淘汰的内存存储，明确重启重置、多实例无共享限制；多实例上线前改共享存储。仅信任显式配置的代理，不能直接信任任意 X-Forwarded-For；测试使用可控时钟，不实际等待窗口。

## 4. HTTP 与 DTO 细化

沿用现有资源路径，批次 A 将以下精确形状写回 contracts，运行时 schema、共享类型及 HTTP 断言保持一致。

| 方法与路径 | 输入 | 成功 |
|---|---|---|
| POST /api/users | email、username、password | 201 UserPublic，设置会话 Cookie |
| POST /api/sessions | identifier、password | 201 SessionCurrent，设置会话 Cookie |
| GET /api/sessions/current | 无 | 200 SessionCurrent；失效 401 |
| DELETE /api/sessions/current | 无业务字段 | 204，无响应体 |
| GET /api/me | 无 | 200 UserPublic；失效 401 |
| PATCH /api/me | username/gender/avatarUrl/signature 的非空子集 | 200 更新后的 UserPublic |

- UserPublic：`{id, username, gender, avatarUrl, signature, createdAt}`；id 字符串，createdAt ISO 时间。公共作者投影保持 M1 的 `{id, username, avatarUrl}`，不自动扩大。
- SessionCurrent：`{user: UserPublic, roles: string[], permissions: string[], expiresAt: string}`；角色/权限只在认证响应出现。不得包含 session token/摘要、邮箱、密码哈希、OAuth subject/token 或内部字段。
- 会话错误沿用 `401 UNAUTHORIZED`；非法 Origin 为 `403 FORBIDDEN`；依赖失败为脱敏 503。数据库写入/会话创建中途失败不得留下可用孤儿身份或无法恢复的注册状态；用事务（需显式配置测试/开发 replica set）或经故障注入验证的补偿/重试方案实现，批次 A 在 ADR 选定一种，不默认为现有 standalone Mongo 支持事务。
- 替换 M1 固定拒绝的 AuthenticatedGuard，但 M2 不开放写书或写评论：匿名 POST 保持 401，有效会话 POST 返回 `403 FORBIDDEN`（能力未开放），且数据不变；同步占位 controller 和测试，不让有效会话继续得到误导的 401，也不提前实现 M3。

## 5. M2b：个人资料与界面

- PATCH 只允许四个可编辑字段，空对象/未知字段拒绝；不允许 email、roles、enabled、id 或 ownerId。username 与注册同规则；大小写仅展示变化可成功，与其他用户归一化冲突返回 409。
- signature 最长 200 Unicode 码点，作为纯文本；拒绝 C0 控制字符（允许换行及制表符），不使用 v-html。gender 只接受上述枚举。
- avatarUrl 仅 null 或最长 2048 字符的 HTTPS 绝对 URL，禁止 userinfo、控制字符及非 HTTPS 协议；不代理抓取、不上传。外链图片使用 no-referrer，失败显示占位；现有 M1 头像如不符合新写入规则，可继续只读显示，不擅自重写数据。
- 前端提供注册、登录、资料页面与导航登录态、退出入口；密码字段正确 autocomplete、label、键盘焦点、提交中禁重复点击、明确错误与重试。登录后只允许回到同源站内安全路径，拒绝外站和 `//` 重定向。
- 刷新时通过 current 恢复身份；401 清空本地登录态，网络/503 显示重试，不能当作明确退出。退出成功后清理资料缓存，资料响应不能在退出后被慢请求回写；登录成功密码不持久化。用户名更新应在重新读取书籍/评论时展示最新公开作者资料，不改资源归属。

## 6. M2c：GitHub OAuth

- 入口 `/api/oauth/github/authorization`、回调 `/api/oauth/github/callback`；首次资料提交新增 `POST /api/oauth/github/registrations`（协议路径），body 仅 username，201 UserPublic 并建立正常会话。
- 使用服务端授权码流程、随机 state、PKCE S256 和浏览器绑定的短期 HttpOnly Cookie；过渡状态服务端保存摘要、verifier、固定回调、到期时间（10 分钟），一次性消费。不能只凭回调中的 subject/email 创建登录身份。
- 实施前查阅 GitHub 官方文档确认当前应用类型对 PKCE 的支持；若与本规格不符，记录依据和安全替代提案，不能悄悄去掉验证或将模拟通过当真实通过。
- 校验 state、浏览器绑定、时效和重放，后端换取 token 并读取稳定 GitHub user id 作为 subject；不使用可变 login 或邮箱作身份主键。token 仅用于本次取身份，不持久化、不回传、不落日志，默认不申请邮箱范围。
- 已有 subject 登录；新 subject 返回站内设置用户名页面，浏览器仅持有短期注册凭证的 HttpOnly Cookie，不能携带 provider token。完成前无普通会话、不能访问 me、不能发布评论；提交接口有 Origin 校验和每 IP 15 分钟 5 次限流。
- OAuth-only 用户邮箱/密码均可空；即使返回邮箱与本地账号一致，也不合并、不占用该邮箱作为密码登录身份。已登录用户点击 GitHub 登录不执行关联，显示明确提示或先退出再开始。
- 并发回调/用户名提交依赖 provider subject、usernameNormalized 唯一索引：最多一个身份映射及用户，失败不得留下孤儿用户；同 subject 重放不能切换绑定。错误、取消授权、上游超时均回到站内稳定错误页，URL 不带 token/code/个人身份信息，不接受任意 returnTo。
- 缺少 GitHub client id/secret 时，应用其他功能可启动，GitHub 入口明确不可用并返回脱敏 503。配置仅记变量名、示例占位和固定回调，不提交真实凭据。真实浏览器登录需可用 GitHub 应用/账号；无人可完成授权时标记 M2c“外部验证阻塞”，M2a/M2b 可独立通过，整个 M2 不能标完成。

## M1：工程与公开书库

- [ ] 固定运行时版本、pnpm workspace、web/API/shared contracts、根开发与检查命令、最小 CI。
- [ ] 配置开发库和独立测试库，健康检查能够反映数据库依赖状态。
- [ ] 明确书籍记录的数据含义、分页/字段边界，完成公开书籍及评论 API、索引和脱敏。
- [ ] 提供可重复导入的本地演示数据：不同阅读状态、详情和评论；仅用于开发/测试，不自动写生产库。
- [ ] 完成列表、筛选、详情、评论读取以及加载/空态/错误态、基本响应式和键盘可用性。
- [ ] 真实 HTTP/浏览器验证公开浏览和隐藏资源隔离；匿名写入不得成功；完成独立审查。

完成标准：干净 checkout 按说明启动后，无需手改数据库就能演示完整公开浏览流程；测试和构建有真实结果。

## M2：账号与资料

- [ ] M2a：邮箱注册、登录、当前会话、退出撤销、密码哈希、限流和 Cookie 安全。
- [ ] M2b：个人资料读取/修改、用户名唯一性和头像来源规则。
- [ ] M2c：GitHub OAuth、state/PKCE、首次用户名设置；不按邮箱静默合并身份。
- [ ] 验证并发唯一性、非法输入、撤销、禁用、敏感信息及认证界面流程。

完成标准：两种登录方式与资料流程分别有证据；缺 GitHub 凭据时可先完成其他部分，但不能将真实 OAuth 登录标记通过。

## M3：发布与互动

- [ ] M3a：发布、查看和维护自己的书籍；明确发布、删除及关联评论生命周期。
- [ ] M3b：发表评论、作者维护评论、管理员处理边界与纯文本安全。
- [ ] 服务端身份决定 ownerId/authorId；验证跨用户越权、重复提交、限流和公开读取。

完成标准：用户 A 发布，用户 B 浏览并评论，A/B 只能维护各自允许的内容；更新和删除行为符合冻结契约。

## M4：管理后台

- [ ] 明确首个管理员初始化、权限矩阵、危险角色操作和最后管理员保护规则。
- [ ] 管理端书籍列表按发布者及状态组合筛选；用户列表和启停能力。
- [ ] 角色管理只允许服务端权限白名单；管理操作审计且敏感字段脱敏。
- [ ] 验证普通用户直接访问 API 被拒绝，禁用账号权限及时失效。

完成标准：管理功能通过真实界面与 HTTP 权限测试；初始化和恢复管理员权限的方法可复现。

## M5：多环境与发布

- [ ] 选择部署目标，固定构建、启动、配置注入、反向代理及 TLS 方案。
- [ ] 建立 staging 与 production，隔离数据库、凭据、OAuth 回调和测试数据。
- [ ] 完成 CI、发布流程、健康检查、日志脱敏、备份恢复演练与应用回滚演练。
- [ ] 在 staging 跑完整用户/管理员流程；发布前独立审查并记录未验证项。
- [ ] 单独决定是否需要 GitHub 外部评论；不作为核心上线前置条件。

完成标准：环境清楚、发布可重复、恢复有证据。部署目标及生产操作按用户实际授权执行，不把本地测试写成已上线。

## 当前下一步

从 M1 开始：确认阅读记录的数据含义，搭建 workspace 和本地数据库隔离，然后实现公开 API 与带演示数据的书库页面。契约测试联合验证方法、路径、状态码和错误结构，并覆盖负向输入，避免只检查文本是否出现。

## 验收记录格式

完成一个里程碑时在本页追加：日期、提交 SHA、交付行为、实际验证命令及退出码、审查结论、剩余问题。状态使用未开始/进行中/待审查/通过/阻塞；没有结果不能勾选完成。较大证据另存专项文件并链接，不预建五份空记录。

GET /api/admin/books?ownerId=&status= 支持服务端组合筛选/分页/排序白名单；GET /api/admin/users、PATCH /api/admin/users/{userId}、GET/POST /api/admin/roles、PATCH /api/admin/roles/{roleId}。匿名 401，普通认证用户 403；敏感字段不返回。

## 5. 依赖排序的实施步骤

1. 先冻结管理员初始化、用户启停、角色/权限白名单和危险变更规则，记录审计输入输出，不让首个注册者自动拥有管理权限。
2. 先写管理员/普通用户/匿名/禁用账号权限矩阵、组合筛选、非法参数与敏感字段失败测试。
3. 实现 admin service/controller 在数据库执行 ownerId+status 筛选、分页和排序；不是前端下载全量再筛选。
4. 实现用户启停和角色绑定，服务端检查权限白名单并记录审计；既有会话对禁用/权限变更按冻结规则生效。
5. 实现管理路由、书籍/用户/角色页面及 loading/empty/error/403 状态，复用共享 DTO；入口可见性不代替后端授权。
6. 真实 API/数据库验证组合查询与索引，浏览器验证筛选和授权；跑认证、所有权和公开脱敏回归。
7. 回填权限矩阵、审计与真实证据，提交推送，交 HSQL-15。

## 6. TDD 测试矩阵

以下是执行目标，除 HANDOFF 明确引用的历史检查外，本合集没有运行这些应用测试。

| 维度 | 先失败的断言/反例 | 正常、边界、错误与回归通过标准 |
|---|---|---|
| 直接 HTTP 权限 | 普通用户绕过前端访问管理资源成功时失败 | 匿名 401、普通用户 403、授权管理员允许，各写接口独立断言 |
| 服务端筛选 | ownerId/status 未生效或只在前端过滤时失败 | 单独/组合条件、空页、非法 ID/状态/排序、分页上限 |
| 禁用与角色 | 禁用用户仍写入、未知权限或越权提权成功时失败 | 权限白名单、已确认危险角色保护、撤销/更新生效与审计 |
| 脱敏/索引 | 返回密码哈希/OAuth/session secret 或无界读取时失败 | 只输出批准字段，真实组合查询正确且有必要索引 |
| 管理 UI/回归 | 无权限显示可成功操作界面或过滤状态错误时失败 | 后台书籍/用户/角色流程、403/empty/error、公开与用户流程不回归 |

RED/GREEN 必须记录同一测试命令和真实退出码，不把语法/安装失败当作行为红测；不删断言、不零测试成功。安全/兼容性/失败回滚要求见 EXECUTION，不得用文档存在替代运行验证。

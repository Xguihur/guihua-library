## 5. 依赖排序的实施步骤

1. 先写列表/详情/筛选的组件与路由失败测试，覆盖加载、成功、空、网络失败及 404。
2. 实现只消费共享 contracts 的 client，将 HTTP 错误映射为稳定界面，不用静态假数据掩盖 API 失败。
3. 实现卡片、阅读状态切换、分页、详情和评论读取；筛选变化正确重置页码并防止旧请求覆盖新状态。
4. 实现封面失败、键盘操作、焦点、移动布局和 prefers-reduced-motion；动画不阻断内容或导航。
5. 连接本地真实 API/MongoDB 跑浏览器 smoke；离线组件 mock 不能替代全链结果。
6. 运行组件/路由、类型、lint 和构建，更新验收记录，交 HSQL-11 做阶段全量验收。

迁移/删除：导出时没有旧业务代码或生产数据可迁移；后续新增索引、状态或身份数据的变更要记录兼容性与回滚。仅清理本任务产生的临时脚手架/日志/验证副本，不删除历史文档、他人改动或生产数据。

## 6. TDD 测试矩阵

以下是执行目标，除 HANDOFF 明确引用的历史检查外，本合集没有运行这些应用测试。

| 维度 | 先失败的断言/反例 | 正常、边界、错误与回归通过标准 |
|---|---|---|
| 页面状态 | loading/empty/error/404 缺失或失败仍显示成功时失败 | 正确渲染公开列表、详情和评论，网络恢复可重试 |
| 路由/筛选/分页 | 切换状态仍显示旧请求结果或页码错乱时失败 | reading/finished 和列表→详情→返回流程保持正确 |
| 资源失败 | 封面失败或不存在详情导致整页不可用时失败 | 封面替代、404 反馈、空评论和分页边界可观察 |
| 可访问/运动 | 键盘不可达或减少动画设置失效时失败 | 可见焦点、合理语义、移动宽度与 reduced-motion 真实浏览器检查 |
| 只读与回归 | 访客 UI 提供能成功写入的操作时失败 | 无发布/评论写入；真实 API smoke、类型和构建通过 |

RED/GREEN 必须记录同一测试命令和真实退出码，不把语法/安装失败当作行为红测；不删断言、不零测试成功。安全/兼容性/失败回滚要求见 EXECUTION，不得用文档存在替代运行验证。

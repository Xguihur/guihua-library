## 5. 依赖排序的实施步骤

1. 锁定待验收提交和环境，确认前置测试/推送证据可重放，而非只读取总结。
2. 干净 checkout 运行冻结安装、类型、lint、离线/契约测试、真 MongoDB 集成、构建和浏览器端到端 smoke。
3. 对照公开/隐藏夹具，实际 HTTP 验证匿名列表、详情、评论、状态筛选、分页、404、400 以及匿名写入不能成功。
4. 记录全部命令、退出码、失败和未验证项；发现缺陷则在批准范围内修复，复跑受影响用例和必要回归。
5. 交给不同 Agent 只读审查锁定 SHA，检查源码、契约、测试有效性、安全、文档及真实结果，不修改实现。
6. 阻塞缺陷经修复与复核关闭后记录阶段结论；只有此时可进入 HSQL-12。

迁移/删除：导出时没有旧业务代码或生产数据可迁移；后续新增索引、状态或身份数据的变更要记录兼容性与回滚。仅清理本任务产生的临时脚手架/日志/验证副本，不删除历史文档、他人改动或生产数据。

## 6. TDD 测试矩阵

以下是执行目标，除 HANDOFF 明确引用的历史检查外，本合集没有运行这些应用测试。

| 维度 | 先失败的断言/反例 | 正常、边界、错误与回归通过标准 |
|---|---|---|
| 全量基线 | 类型/lint/test/build/集成任一失败应阻塞 | 干净 checkout 全部命令通过，无 skip 掩盖 |
| 访客链路 | 隐藏数据可见、筛选错误或匿名写入成功应阻塞 | 列表→筛选→详情→评论的真实 HTTP/浏览器流程 |
| 契约回归 | 方法/路径/状态/DTO 漂移应失败 | OpenAPI/schema 与 web/API 行为一致，敏感数据不泄漏 |
| 审查证据 | 未锁定 SHA、缺独立意见或未处理阻塞应阻塞 | 分级发现、文件/符号证据、重测与无阻塞结论齐全 |

RED/GREEN 必须记录同一测试命令和真实退出码，不把语法/安装失败当作行为红测；不删断言、不零测试成功。安全/兼容性/失败回滚要求见 EXECUTION，不得用文档存在替代运行验证。

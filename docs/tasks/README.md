# 任务规格与验收规范

后续开发任务的规格、测试矩阵、验收命令、真实结果、缺陷和结论统一放在 `docs/tasks/`。这些文档属于 monorepo 外部统一文档区，**不得**放入 `apps/web`、`apps/api` 或 `packages` 的内部目录。

## 文件命名

每个阶段使用 `HSQL-<number>.md`，文件名必须与平台任务编号一致。任务拆分或契约变更不能覆盖历史验收证据；需要新范围时创建新版本或新任务文档，并链接前置记录。

## 必备章节

```markdown
# HSQL-N：任务标题

- 计划版本：v1.2
- 前置任务：HSQL-N-1
- 范围：...
- 非目标：...
- 契约映射：...

## TDD 测试矩阵
### 先失败
### 正常路径
### 边界、错误、重复调用与回滚
### 安全/兼容性

## 实现与变更范围
## 验收命令
## 真实结果
## 缺陷与未决项
## 验收结论
```

## 编写要求

1. 先引用批准计划、RESTful 契约、ADR 和前置任务；需求变化、契约冲突或计划遗漏必须停止实现并回到规划审核，不得在任务文档中擅自改范围。
2. TDD 矩阵必须覆盖正常、边界、错误、重复调用、失败回滚、兼容性和安全约束。先写能表达契约的失败测试，再实现最小行为；不得删除有效断言或用快照替代行为断言。
3. 验收命令必须可从干净工作树复现。记录完整命令、退出状态、关键输出和环境前提；“未运行”“无法验证”必须明确标注，不能写成通过。
4. 证据只记录真实结果：测试、类型检查、lint、构建、契约检查、数据库集成和真实 smoke 按任务范围列出。不要把源码存在、mock 回声或“不抛异常”当作行为验收。
5. 记录契约路径、HTTP 方法、状态码、过滤、错误码、权限、脱敏和数据边界的映射。RESTful 资源必须与 [`../contracts/restful-api.md`](../contracts/restful-api.md) 一致。
6. 记录变更文件范围和未改动的非目标目录；禁止密钥、真实环境变量、生产数据和临时脚手架进入仓库。
7. 任务完成前清理 throwaway 脚本、mock endpoint、无效 fallback 和 TODO 实现；只有用户可观察且可复现的回归测试保留。

## 状态判定

- **未开始**：没有实现或验收证据。
- **进行中**：实现或测试仍在执行，不能声明通过。
- **待审查**：执行工程师已完成命令并记录结果，等待独立只读审查。
- **通过**：验收标准全部有证据，阻塞缺陷关闭，审查结论无阻塞项。
- **阻塞**：存在失败、缺失证据、契约冲突或未决安全问题；必须列出根因和下一步，不得用降级断言标记通过。

HSQL-7 只建立本规范及方案、契约和 ADR 文档，不创建业务实现或 mock endpoint。
